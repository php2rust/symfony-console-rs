# Symfony String

A port of `symfony/string` v8.1.10 (`6c611097`):
ByteString, CodePointString and UnicodeString with what AbstractString and
AbstractUnicodeString give them, the `u()`, `b()` and `s()` functions, the
PHP functions they call, LazyString, and the English, French and Spanish
inflectors. MIT; Symfony source, tests and the wcswidth
tables copyright Fabien Potencier. Unofficial, not affiliated with or
endorsed by Symfony.

The abstract classes are the trait `AbstractString` (import it to call the
methods); `string|iterable` arguments are a `Needle`, a callable `$to` a
`Replacement`, `bool|TruncateMode` a `TruncateMode`. Strings are bytes.
Methods that throw in PHP return `Result<_, Error>`.

## Dependencies

`unicode-normalization` (NFC, NFD, NFKC, NFKD) and `unicode-segmentation`
(graphemes), from unicode-rs, checked against the oracle above, not
trusted; `php-pcre` (the workspace's PCRE translator, moved out of
symfony-finder) and `php-value` (what `match()` and `wrap()` return).

## Differences

- **Unicode version.** The oracle's ICU and PCRE2 implement Unicode 15.0;
  the crates implement a newer version. 93 code points that extend a
  grapheme and 2 that prepend one are assigned only after 15.0: PHP treats
  them as unassigned characters (each its own grapheme), this crate as
  marks (`per_code_point_classes_differ_only_after_unicode_15`). Case
  mappings and NFKC_CF are the oracle's, so they do not differ.
- **Indic conjuncts in `length()` and `slice()`.** The crate applies the
  conjunct rule (GB9c, Unicode 15.1); ICU 72.1 has its own older handling
  (ICU-21661): `अनुच्छेद` is 4 graphemes here and 5 in the oracle. Upstream's
  tests skip those rows on such an implementation, and so does the port.
  `chunk()` and `wordwrap()` follow PCRE2, which has no conjunct rule, and
  match the oracle.
- **ICU's search.** `grapheme_*pos()` search with ICU's collator: the port
  matches canonically equivalent text, skips the code points NFKC_CF
  removes (default ignorables such as U+200B and U+200C) and folds case
  simply, which reproduces all recorded answers but two kinds: ICU folds
  the ligature U+FB01 like "fi" (but not U+00DF like "ss"), and
  `grapheme_strrpos()` of a needle of ignorable code points only fails on a
  haystack ending in a combining sequence (`known_difference` in
  `tests/builtins.rs`).
- **`fromRandom()`** reads the operating system's CSPRNG through
  `getrandom`, as PHP's `Random\Randomizer` does (PLAN.md, decision 15).
  If that source fails, the error carries `getrandom`'s text where PHP
  throws `Random\RandomException`. `from_random_with()` takes the bytes
  from the caller instead; each byte is still chosen uniformly from the
  alphabet.
- **Pattern errors.** `match()`, `replaceMatches()` and `split()` with
  flags compile patterns with php-pcre: a pattern PHP rejects is an
  `InvalidArgumentException` whose text is php-pcre's, not PCRE2's; a
  feature php-pcre does not translate, and named groups (which `match()`
  would also return by name), are refused (`Error::Unsupported`). After an
  empty match the next search starts one character on.
- **Encodings.** `toByteString()` and ByteString's conversions know
  UTF-8, Windows-1252 (mbstring) and windows-1250 (the `iconv()`
  fallback); other encodings are refused.
- **LazyString's callables.** PHP finds a callable's kind and name by
  reflection; here the caller gives the name (`Callable::new()`,
  `Callable::method()`), so the TypeError text is as exact as that name.
  Arrays PHP accepts as lazy-callables and then fails on when cast (three
  items, a non-string method, a factory returning a class name) cannot be
  built; `check_callable_array()` keeps the check for arrays that arrive
  as values. `fromStringable()` and `resolve()` of null, an array or a
  plain object give PHP's TypeError without its ", called in FILE on line
  N" suffix. A Stringable is one by its type (the `Stringable` trait), so
  `isStringable()` of a php-value object is false; there are no
  resources. A cast from inside the LazyString's own callback is refused
  (`Thrown::Recursion`) where PHP recurses until it runs out of stack. If
  a lazy-callable's method is undefined, PHP's next cast calls the object
  itself; the port calls the method again.
- `split()` with `PREG_SPLIT_OFFSET_CAPTURE` is `split_offsets()`, since
  its chunks carry offsets; `s()` returns the `Str` enum.

## Not ported

`ascii()` and `localeLower()`, `localeUpper()`, `localeTitle()` need ICU's
transliterators (`any-latin/bgn`, locale rules) and are refused
(`testAscii`, `testAsciiClosureRule`, `testLocale*`: 10 rows pending);
the Slugger (AsciiSluggerTest and SluggerTest, 20 rows) depends on them.
Their manifest rows stay `pending`.
